# 영양소 ④ 식품원·함량 재발 방지 규칙 — 2026-10-15

이 문서는 영양소 원고의 ④에서 **식품 후보 누락, 동일 원료 파생품으로 순위 채우기, 추정값 순위화, 작성자의 조사·변명 과정이 독자 본문으로 노출되는 문제**를 막기 위한 영구 작성 규칙이다.

## 1. 독자가 묻는 질문부터 고정한다

④의 핵심 질문은 하나다.

**`이 성분은 어떤 식품·원료에 얼마나 들어 있는가?`**

첫 문장과 표는 이 질문에 바로 답해야 한다. `왜 순위를 만들기 어려운가`, `자료가 왜 서로 다른가`, `어떤 분석법을 썼는가`를 먼저 설명하지 않는다.

## 2. 식품원 후보군을 먼저 넓게 조사한다

- 주제 성분의 `food source / dietary source / occurrence / quantitative analysis` 자료를 확인한다.
- 식물성 성분은 대표 종 하나만 보지 말고 같은 속·가까운 식용 식물과 국내 통용 원료명까지 후보를 확인한다.
- 대표 급원이라는 사실과 다른 식품에도 존재한다는 사실을 별도로 확인한다.
- `검출됨`과 `실제 고함량 급원`을 구분한다. 검출만 확인된 식품을 고함량 급원처럼 쓰지 않는다.

## 3. 존재 확인과 순위화를 분리한다

- 먼저 어떤 식품에서 해당 성분이 확인되는지 후보 목록을 만든다.
- 그 다음 동일 DB·동일 상태·동일 단위·동일 분석 기준처럼 직접 비교 가능한 항목만 TOP7/TOP5/TOP3에 넣는다.
- 비교 가능한 3개 식품도 없으면 순위를 만들지 않는다.
- 순위를 만들지 않더라도 확인된 함량 정보 자체를 버리지 않는다. 독자에게 유용하면 **비순위 표**로 보여준다.

## 4. 독자용 표의 기본 형태

기본 표는 다음처럼 독자가 원하는 정보만 중심에 둔다.

| 식품·원료 | 함량 | 기준 | 실제 섭취 참고 |
| --- | ---: | --- | --- |
| 식품 A | 값 | 생것·건조·100g·1회량 등 | 필요할 때만 |

기본 열로 만들지 않는 것:

- 확인된 내용
- 함량을 읽는 방법
- 연구 조건
- 분석법
- 추출법
- DB 비교 과정
- 작성자가 순위를 포기한 이유

이런 내용은 독자 판단에 반드시 필요한 경우에만 표 아래 한두 문장으로 짧게 보조한다.

## 5. 기준이 다른 값의 처리

- 기준이 다르다고 함량 자체를 숨기지 않는다.
- 생것·건조분말·추출물처럼 기준이 다른 경우 `기준` 열에 정확히 표시하고 비순위 표에서 각각 보여줄 수 있다.
- 직접 비교할 수 없는 값을 한 줄 세워 순위를 만들지는 않는다.
- 필요한 설명은 예를 들어 `※ 생것과 건조분말은 기준이 달라 순위 비교하지 않았습니다.` 정도의 한 문장으로 끝낸다.
- 이 판단 과정 자체를 본문의 중심 주제로 확대하지 않는다.

## 6. 서로 독립된 식품을 순위화한다

- 하나의 핵심 원료를 배합한 가공품 여러 개를 서로 다른 천연 급원처럼 취급하지 않는다.
- `강황가루 → 강황 4.2% 카레 → 강황 2.8% 카레`처럼 같은 원료의 배합률만 다른 제품으로 TOP3를 채우지 않는다.
- 가공 형태 비교가 검색 의도상 필요하면 `섭취 형태 비교`로 따로 설명한다.

## 7. 추정값으로 TOP 순위를 만들지 않는다

- `원료 실측 함량 × 가공식품 속 원료 배합률`처럼 계산한 값은 순위 근거로 사용하지 않는다.
- 실측값과 계산·환산·추정값을 같은 TOP 표에서 비교하지 않는다.
- 추정값은 실제 섭취량 설명에 꼭 필요할 때만 순위표 밖에서 `추정`이라고 명시한다.

## 8. 평균·범위·실측·추정을 구분한다

- 실제 평균값만 `평균 함량`이라고 쓴다.
- 범위 자료는 범위로 표시한다.
- 단일 분석값은 단일값으로 표시한다.
- 제품 표시량·최저 보장량·배합비 환산값을 식품 자체의 평균 함량으로 바꾸지 않는다.

## 9. 조사 메모와 공개 본문을 분리한다

작성자는 내부적으로 다음을 확인할 수 있다.

- 원문 논문
- DB 이름
- 분석법
- 표본 수
- 식물 학명·부위
- 추출 조건
- 비교 가능 여부
- 순위 가능 여부

하지만 이것들은 **사실을 검증하기 위한 내부 정보**다. 독자가 `어디에 얼마나 들어 있는가`를 이해하는 데 필요하지 않으면 본문에 옮기지 않는다.

금지되는 기본 흐름:

`자료가 서로 다름 → 비교가 어려움 → 왜 순위를 못 만드는지 설명 → 마지막에 식품 이름 몇 개 제시`

권장 흐름:

`식품 이름과 함량 제시 → 기준 표시 → 꼭 필요한 차이만 한두 문장 설명`

## 10. 저장 전 필수 확인

④를 완료하기 전에 한 번만 확인한다.

- 다른 식품·같은 속의 식용 식물까지 후보를 조사했는가?
- 표의 첫눈에 보이는 정보가 식품명과 함량인가?
- TOP 항목이 서로 독립된 식품인가?
- 순위 수치가 직접 비교 가능한 값인가?
- 추정·환산·배합률 계산값을 TOP 순위에 넣지 않았는가?
- 동일 기준 3개가 없을 때 억지 TOP3 대신 비순위 표로 바꿨는가?
- 기준이 다른 확인된 수치를 `비교 불가`라는 이유로 아예 숨기지는 않았는가?
- 작성자의 연구·DB·분석·QA 설명이 독자 본문을 차지하고 있지는 않은가?
- `왜 이렇게 작성했는가`보다 `어디에 얼마나 있는가`에 더 많은 공간을 썼는가?

## 11. 기술 검사와 역할 분리

`nhunnhun_blog`의 direct/SP1 preflight는 TOP 순위에 추정값을 사용하는 것처럼 명백한 구조 오류를 차단한다.

식품 후보군의 충분성, 독립 식품 여부, 독자가 실제로 원하는 답인지 여부는 단순 regex나 자동 의미 판정으로 대신하지 않는다. `PROJECT_INSTRUCTIONS.txt`의 저장 전 내용 검토에서 한 번 확인한다.

새 AI 의미 판정·자동 재작성 루프는 추가하지 않는다.
