# 한입 건강 — 영양소 카테고리 프로젝트 지침 R9
개정일: 2026-10-15

## 1. 적용 범위와 우선순위
- 대상은 https://nhunnhun.tistory.com/ 의 영양소 카테고리다.
- 영양소의 내용·검색 의도·6개 소주제·문체·표·강조·이미지·내부링크 기준은 이 파일을 최우선 편집 기준으로 한다.
- 실제 티스토리 제출·공개 검증은 ansqhd5774-Choi/nhunnhun_blog의 공통 direct/SP1 기술 계약과 workflow를 따른다.
- 다른 카테고리의 편집 지침과 legacy 원고는 영양소 작성 기준으로 사용하지 않는다.
- 사용자 지시가 이 문서보다 우선한다. 기존 URL·articleId·미변경 원고·원장은 보존한다.

## 2. 글의 목적 — 독자 질문에 답한다
- 기본 독자는 영양학 전공자가 아닌 한국 일반 독자다. 중학생~고등학생이 한 번 읽고 핵심을 이해할 정도를 기본 난이도로 한다.
- 글의 목적은 논문·연구·DB를 설명하는 것이 아니라 독자가 검색한 질문을 해결하는 것이다.
- 전문성은 연구 용어의 개수가 아니라 **정확한 답·수치·조건·행동을 짧고 쉽게 전달하는 것**으로 판단한다.
- 제목과 각 H2는 독자가 실제로 궁금해하는 질문이어야 하며, 첫 문장에서 답부터 준다.
- 한 문단은 가능하면 2~4문장 안에서 `답 → 필요한 이유·수치 → 실제 행동`으로 끝낸다.
- 확인된 효능·장점·실용 정보를 먼저 쓴다. 일반적인 반박·한계·방어 문구를 반복해 글의 중심으로 만들지 않는다.

## 3. 조사 근거와 공개 본문을 분리한다
- 정부·공식 영양 DB·전문기관·진료지침·원문 연구는 **작성자가 사실을 확인하는 내부 근거**다.
- 공개 본문에는 그 근거를 확인해 얻은 **최종 답·필요한 숫자·조건·실천 정보**를 우선한다.
- `연구에서는`, `논문에서는`, `임상시험에서는`, `무작위 대조시험`, `표본수`, `분석법`, `통계값`, `DB가 달라`, `비교가 어려워` 같은 표현은 독자 판단에 꼭 필요하지 않으면 본문에서 제거한다.
- 연구 설계·표본수·통계값을 지워도 결론이 그대로라면 지운다. 출처 링크와 내부 근거에는 남길 수 있다.
- 작성자의 조사 과정, 자료 선별 과정, QA 과정, 순위를 만들거나 포기한 이유를 독자용 설명으로 쓰지 않는다.
- `왜 TOP3를 만들지 않았는가`, `왜 이 수치를 직접 비교하지 않았는가`, `어떤 분석법을 썼는가`는 독자의 질문일 때만 짧게 설명한다.
- 근거 수준 때문에 대상·용량·기간·해석이 달라지는 경우에는 그 차이만 독자가 이해할 말로 남긴다.
- 기본 변환은 `근거 확인 → 사실 추출 → 독자용 답으로 변환`이다. `논문 요약 → 본문`으로 바로 옮기지 않는다.

## 4. 검색 의도·중복·전체 최신화
- 동일 검색 의도의 기존 글은 숫자 URL과 articleId를 유지해 전체 최신화한다. 중복 신규 글을 만들지 않는다.
- 전체 최신화에서 유지하는 것은 URL·articleId와 현재도 유효한 사실·출처·이미지 자산뿐이다.
- 기존 H2 순서·소제목 문구·문단 배열을 새 원고의 골격으로 복사하지 않는다.
- 먼저 아래 ①~⑥의 빈 골격을 만들고 최신 조사 결과를 배치한다.
- 글을 쓰기 전에 독자가 실제로 알고 싶은 질문을 최대 6개로 확정한다.
- 실제 검색량 자료가 없으면 검색량·노출률 수치를 만들지 않는다.
- FAQ·자료 출처는 보조 영역이며 핵심 H2 6개에 포함하지 않는다.

## 5. 기본 구조
신규 및 전체 수정은 다음 순서를 사용한다.

`대표 이미지 → 짧은 도입 → 핵심만 먼저 6카드 → ①~⑥ → FAQ → 자료 출처`

- 하단에 같은 내용을 반복하는 `핵심 정리` H2는 만들지 않는다.
- 핵심 H2는 최대 6개다.
- 상단 6카드는 `효능 / 누가 / 복용 / 기간 / 조합 / 주의` 순서로 고정한다.
- 카드는 본문을 다 쓴 뒤 최종 수치와 표현을 압축한다. 카드에만 있는 새로운 주장·수치·제품을 만들지 않는다.
- 카드에는 연구 설계·표본수·긴 기전·출처 설명·여러 예외 조건을 넣지 않는다.

## 6. 영양소 6개 소주제

### ① 정의·주요 성분·작용
- 무엇인지, 몸에서 어떤 일을 하는지, 비슷한 성분과 무엇이 다른지 설명한다.
- 기전은 효능 이해에 필요한 만큼만 쓴다.
- 전문용어가 꼭 필요하면 `쉬운 한국어(전문용어)` 순서로 첫 등장 한 번만 설명한다.

### ② 효능·기대 변화·권장 대상·제품 형태
- 먼저 **무엇이 좋아질 수 있는지** 답하고, 그 효능에서 해당 대상을 역으로 연결한다.
- 사람 근거가 있는 효능은 작성 단계에서 `누가 / 얼마를 / 얼마나 오래 / 무엇이 변했는가`를 확인한다.
- 공개 본문은 연구 보고서처럼 쓰지 않는다. 기본 문장은 `대상 + 섭취량 + 기간 + 실제 변화`로 바로 쓴다.
- 예: `무릎 골관절염이 있는 성인이 커큐민 500mg을 하루 2회, 8주 섭취했을 때 통증과 걷기 기능이 개선된 결과가 있습니다.`
- 같은 사실을 `101명을 대상으로 한 무작위 대조시험에서…`처럼 시작하지 않는다. 표본수·시험 설계가 결론 적용에 꼭 필요할 때만 보조한다.
- 특정 하위군에서만 변화가 확인됐다면 일반 성인 전체로 넓히지 않는다.
- 세포·동물 결과만으로 사람 권장 대상을 만들지 않는다.
- 음식·단일성분·복합제 중 어떤 형태가 목적에 맞는지 실제 선택에 필요한 범위에서 설명한다.

### ③ 실제 섭취량·복용법·기간·대표 제품
- 독자가 바로 써먹을 수 있게 `1회량 / 하루 횟수·알 수 / 언제 / 식전·식후 / 처음 점검할 시점`을 우선한다.
- 공식 권장량·충분섭취량·상한이 있으면 먼저 제시한다.
- 공식 권장량이 없는 기능성 성분은 제품 표시량과 사람 자료에서 사용된 양을 구분한다.
- 사람 자료의 관찰기간은 첫 점검 참고 시점으로 쓸 수 있지만 효과 보장기간처럼 표현하지 않는다.
- 임의로 8~12주 같은 범위를 만들지 않는다.
- 국내 판매 제품 예시는 제조사·공식 판매처·식품안전나라 등 현재 공식 자료로 제품명·1회량·하루 복용법·성분량을 확인한다.
- 객관적 판매순위·판매량·리뷰 자료가 없으면 `가장 인기`라고 쓰지 않고 `대표 제품 예시`라고 쓴다.

### ④ 풍부한 식품과 실제 함량
- 이 H2의 핵심 질문은 **`어디에 얼마나 들어 있는가?`**다. 첫 문장과 표가 이 질문에 바로 답해야 한다.
- 순위를 만들기 전에 성분이 존재하는 식품 후보군을 넓게 조사한다. 식물성 성분은 대표 종 하나만 보지 말고 같은 속·가까운 식용 식물과 국내 통용 원료명도 확인한다.
- `검출됨`과 `실제 고함량 급원`을 구분한다. 검출됐다는 사실만으로 고함량 식품처럼 쓰지 않는다.
- 동일 DB·동일 상태·동일 단위 등 직접 비교 가능한 독립 식품이 충분하면 TOP7을 우선한다. 부족하면 TOP5→TOP3로 줄인다.
- 비교 가능한 3개도 없으면 **순위를 만들지 말고 확인된 식품과 함량을 그대로 보여준다.** 순위를 못 만든 이유를 장황하게 설명하지 않는다.
- 기준이 다른 값도 독자에게 유용하면 버리지 않는다. `식품·원료 / 함량 / 기준(생것·건조·100g·1회량)` 형태의 비순위 표로 보여주고 필요한 차이는 표 아래 한두 문장으로만 설명한다.
- 표의 중심은 식품명과 실제 함량이다. `확인된 내용`, `함량을 읽는 방법`, `연구 조건`, `분석 방식` 같은 작성자용 열을 기본 열로 만들지 않는다.
- 하나의 원료를 넣은 가공품 여러 개로 순위를 채우지 않는다. 예: `강황가루 → 강황 4.2% 카레 → 강황 2.8% 카레` 금지.
- `원료 실측 함량 × 배합률` 같은 추정·환산·계산값으로 TOP 순위를 만들지 않는다.
- 실측값과 추정값을 같은 순위표에서 비교하지 않는다. 추정값이 실제 섭취 설명에 꼭 필요하면 순위 밖에서 `추정`이라고 밝힌다.
- 실제 평균값만 `평균 함량`이라고 쓴다. 범위는 범위, 단일 측정값은 단일값으로 표시한다.
- 향신료·건조분말처럼 100g 섭취가 비현실적이면 실제 1회 사용량도 함께 설명한다.
- 상세 검토 규칙은 `docs/NUTRIENT_FOOD_SOURCE_RANKING_GUARD_20261015.md`를 따른다.

### ⑤ 함께 섭취할 영양소·보충제 조합
- 음식 궁합보다 `영양소/기능성 성분 + 영양소/기능성 성분` 조합을 우선한다.
- 각 조합은 `A+B → 왜 같이 먹는가 → 같이 먹는 방법·시간 → 기대 이점 → 중복·상한·약물 주의` 순서로 설명한다.
- 실제 함께 먹은 결과와 성분 수준의 기전 설명을 구분한다.
- 복합제품 결과를 각 성분의 단독 효과로 바꾸지 않는다.
- 강한 조합이 1~2개뿐이면 그 수만 제시한다. 개수를 채우기 위해 약한 조합을 억지로 추가하지 않는다.

### ⑥ 결핍·과다 섭취
- 결핍 증상·위험군·확인 방법과 과다 시 부작용·상한·중단/상담 기준에 집중한다.
- 기능성 성분처럼 결핍증이 정의되지 않은 성분은 억지 결핍 질환을 만들지 않는다.
- 제품 선택을 반복하지 않는다.
- 응급 증상·중요 금기는 행동 기준을 분명히 적는다.

## 7. 자료 선택 기준과 자료 표시 기준
- **좋은 자료를 찾는 기준과 독자에게 보여주는 문장 형식은 별개다.**
- 자료 선택은 정부·공식 DB·전문기관·진료지침·원문 연구를 우선한다.
- 공개 본문은 기관명·DB명·논문 제목·분석법을 나열하기보다 그 자료에서 확인한 답을 먼저 쓴다.
- 권장량·충분섭취량·상한·사람 자료의 섭취량·제품 표시량·유효성분량을 서로 구분한다.
- 원료량을 유효성분량처럼 쓰지 않는다.
- 해외 제품 용법으로 국내 제품 복용법을 덮어쓰지 않는다.
- 출처는 필요한 문장 뒤의 간결한 링크 또는 하단 `자료 출처`에 둔다.
- 사실 확인에 사용한 세부 메모는 원고 본문을 채우기 위한 재료가 아니다.

## 8. 쉬운 문체와 정보 밀도
- 본문·제목·H2·표·핵심카드는 한국 일반 독자가 실제로 쓰는 말을 기본값으로 한다.
- 학명·영문명·균주명·가공공정명·연구 설계명은 없어도 정확성이 유지되면 쓰지 않는다.
- 연구 설계명이 필요하지 않으면 `사람 연구`, `임상시험`으로 바꾸어 남기는 것이 아니라 **연구 표현 자체를 생략하고 확인된 결과를 바로 쓴다.**
- 약어·전문 단위는 실제 선택에 필요할 때만 사용한다.
- 한 문장에는 가능하면 핵심 개념 하나와 중요한 숫자 하나 정도만 둔다.
- 기본 표현 순서는 **`쉬운 답 → 필요한 숫자·조건 → 행동`**이다. 전문 근거는 독자 판단에 꼭 필요할 때만 본문에 짧게 남긴다.
- 같은 수치를 도입·카드·본문·FAQ에서 반복하지 않는다.
- 안전 경고는 유지하되 관련 H2 또는 ⑥에 모은다. 경고를 글의 첫 인상이나 분량 채우기 수단으로 쓰지 않는다.

## 9. 상단 요약·강조
- source HTML의 상단 요약은 다음 의미 구조를 사용한다.
  `<blockquote><strong>핵심만 먼저:</strong> <strong>효능</strong> ...<br><strong>누가</strong> ...<br><strong>복용</strong> ...<br><strong>기간</strong> ...<br><strong>조합</strong> ...<br><strong>주의</strong> ...</blockquote>`
- 공통 `publishing/direct-design.mjs`가 PC 2열·모바일 1열 카드로 렌더링한다. 원고별 inline CSS를 추가하지 않는다.
- 영양소 direct/SP1 강조 누락 방지 하한은 **strong25·mark14·mark>u>strong8**이다.
- 하한을 채우기 위해 없는 효능·수치·위험을 만들지 않는다.
- 강조의 첫 기준은 `현재 H2의 질문에 가장 직접 답하는가`다.
- strong은 정의·핵심 수치·보조 설명, mark>strong은 핵심 답과 실제 행동 정보, mark>u>strong은 글에서 가장 중요한 효능·실천 행동에 우선한다.
- TOP 순위표가 있으면 1위는 최고강조를 우선하고 2·3위는 최소 mark>strong으로 표시한다. 순위 자체는 기본 `info` 톤을 사용한다.
- `positive / info / caution / negative` 톤은 의미 구분용이며 색 종류를 채우기 위해 문장을 만들지 않는다.
- 즉시 위해를 막아야 하는 금기·응급 행동은 예외적으로 강하게 강조할 수 있다.

## 10. 이미지·내부링크
- 신규 및 전체 수정은 서로 다른 본문 이미지 최소 3개를 사용한다.
- HTTPS·alt·원출처·저작자·라이선스·중복을 확인한다.
- 대표 이미지는 성분의 실제 사용 목적·섭취 맥락을 일반 독자가 즉시 이해할 수 있는 실사를 우선한다.
- imageReview와 visualChecked는 공통 direct 계약을 따른다. 실제 현재 revision을 확인하지 않고 visualChecked=true를 복사하지 않는다.
- 내부링크는 실제 관련 글만 연결한다.

## 11. 작성 순서와 저장 전 내용 검토
작성 흐름은 다음을 기본으로 한다.

`검색 의도·중복 → 독자 질문 → 근거 조사 → 내부 사실 정리 → 6개 H2 작성 → 상단 6카드 → 강조·이미지·링크 → 내용 검토 → Gate 0`

- **내부 사실 정리와 공개 본문을 분리한다.** 내부 메모에는 논문·DB·표본·분석법·비교 가능성 판단을 남길 수 있지만 이를 그대로 본문에 복사하지 않는다.
- 저장 전 내용 검토는 한 번만 수행하며 다음을 확인한다.
  1. 각 H2 첫 문장이 독자 질문에 바로 답하는가?
  2. 이 문단은 독자에게 필요한 답인가, 작성자의 조사·검증·변명인가?
  3. `연구/논문/시험/DB/분석법` 표현을 지워도 뜻이 유지된다면 지웠는가?
  4. ②가 `누가·얼마·기간·변화`를 정확히 담되 연구 보고서처럼 쓰이지 않았는가?
  5. ③의 복용량·횟수·시간·점검 시점이 실제 기준과 일치하는가?
  6. ④의 첫 답과 표가 `어디에 얼마나`를 직접 보여주는가? 작성자용 비교 설명이 표의 중심이 되지 않았는가?
  7. ④ 순위가 독립 식품·직접 비교 가능한 값으로만 구성됐고 추정값을 순위에 넣지 않았는가?
  8. ⑤ 조합과 ⑥ 결핍·과다 역할이 섞이지 않았는가?
  9. 상단 카드·강조가 본문 핵심 답과 일치하는가?
- 별도 가독성 점수·AI 의미 PASS·자동 재작성 루프를 만들지 않는다.
- Gate 0·preflight·공개검증에서 같은 의미·문체 검토를 반복하지 않는다.

## 12. Gate 0·GitHub 저장
- GitHub 쓰기 전에 완성 JSON 전체와 sourceId·articleId·title·digest·검사 상태를 보존한다.
- 실제 commit SHA에 고정한 파일을 다시 읽고 내용과 digest가 일치해야 `GITHUB_SOURCE_CONFIRMED`다.
- WRITE_BLOCKED·파일 부재·조회 불가·내용 불일치를 구분한다.
- 재개 시 같은 source의 저장·원장·실행 상태부터 확인한다.

## 13. 표준 실행·공개 검증·복구
- 영양소 저장소 저장만으로 발행 완료라고 하지 않는다.
- 신규는 `publish-posts.yml`, 기존 수정은 `direct-author-update.yml → update-posts.yml`을 사용한다.
- 자동 실행과 수동 실행을 겹치지 않는다.
- 제출 전 실패이고 제출 단계가 시작되지 않았다면 원인을 직접 수정하고 같은 source로 재실행한다.
- 이미 PASS한 검사와 원고 조사를 변경 근거 없이 반복하지 않는다.
- HTTP200·SUBMIT_CLICKED·Actions SUCCESS만으로 완료라고 하지 않는다.
- 해당 source의 `PUBLIC_VERIFIED`와 신규 `published`/기존 `updated` 원장을 확인한다.
- 제출 후 상태가 불명확하면 임의 재제출하지 않고 읽기 전용 복구 경로를 사용한다.

## 14. 변경 보호·보고
- 승인 없는 reset·force push·기존 원고/원장 삭제·중복 발행·URL·articleId·카테고리·스킨·광고 변경을 하지 않는다.
- 작성·내용 검토·기술 검사·GitHub 저장 확인·실행·제출·공개 검증을 구분한다.
- 확인하지 않은 결과를 PASS라고 하지 않는다.
- 최종 보고는 source SHA·Run·공개 URL·원장 상태·중요한 문제만 간결하게 작성한다.
