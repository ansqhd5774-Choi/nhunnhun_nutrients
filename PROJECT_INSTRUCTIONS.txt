# 한입 건강 — 영양소 카테고리 프로젝트 지침 R13
개정일: 2026-10-16

## 1. 적용 범위와 우선순위
- 대상은 https://nhunnhun.tistory.com/ 의 영양소 카테고리다.
- 영양소의 내용·검색 의도·소제목·문체·표·강조·이미지·내부링크 기준은 이 파일을 최우선 편집 기준으로 한다.
- 실제 티스토리 제출·공개 검증은 ansqhd5774-Choi/nhunnhun_blog의 공통 direct/SP1 기술 계약과 workflow를 따른다.
- 다른 저장소·다른 카테고리·legacy 원고·과거 자동작성 프롬프트를 영양소 편집 기준으로 사용하지 않는다.
- 사용자 지시가 이 문서보다 우선한다. 기존 URL·articleId·미변경 원고·원장은 보존한다.

## 2. 독자와 글의 목적
- 기본 독자는 건강과 영양에 관심 있는 한국 일반 독자다.
- 중학생~고등학생이 한 번 읽고 핵심 뜻과 실제 행동을 이해할 정도의 난이도를 기본으로 한다.
- 글은 독자가 `무엇인지 / 먹으면 어떤 점이 좋은지 / 누구에게 필요한지 / 얼마나 어떻게 먹는지 / 어떤 식품에 얼마나 있는지 / 무엇과 같이 먹는지 / 부족하거나 많이 먹으면 어떤 문제가 있는지 / 어떤 제품을 고를지`를 빠르게 알 수 있게 작성한다.
- 전문성은 어려운 용어·자료 유형·통계 설명이 아니라 **정확한 답·숫자·조건·행동을 쉽고 구체적으로 전달하는 것**으로 판단한다.
- 각 H2 첫 문장은 질문의 답부터 쓴다. 한 문단은 가능하면 `답 → 필요한 숫자·이유 → 실제 행동` 순서로 2~4문장 안에서 끝낸다.
- 고정 글자수는 두지 않는다. 짧아도 되지만 **각 H2의 질문에 필요한 답을 끝까지 제공한 뒤 다음 소제목으로 넘어간다.**

## 3. 작성자 확인 과정은 본문이 아니다
- 작성자는 수치·함량·복용법·안전성·제품 정보를 틀리지 않도록 신뢰할 수 있는 자료를 충분히 확인한다.
- 공개 본문은 **확인한 최종 사실과 독자에게 필요한 행동 정보**만 전달한다.
- 독자가 실제로 알고 싶어 하는 답을 먼저 쓰고, 자료를 찾거나 비교한 과정은 본문 중심 내용으로 만들지 않는다.
- 확인하기 어려운 내용을 부정 문장으로 길게 설명해 분량을 채우지 않는다. 대신 해당 소제목에서 독자에게 필요한 다른 실용 정보를 더 확인한다.
- 실제 혼동을 바로잡아 독자의 선택이나 안전을 바꾸는 경우가 아니면 오해 정정 문장으로 분량을 채우지 않는다.
- 실제 부작용·상한·약물 상호작용·알레르기·임신·수유·금기·중단 기준처럼 독자의 안전과 행동을 바꾸는 정보는 분명하게 유지한다.

## 4. 검색 의도·중복·전체 최신화
- 동일 검색 의도의 기존 글은 숫자 URL과 articleId를 유지해 전체 최신화한다. 중복 신규 글을 만들지 않는다.
- 전체 최신화에서 유지하는 것은 URL·articleId와 현재도 유효한 사실·출처·이미지 자산뿐이다.
- 기존 H2 순서·문구·문단 배열을 자동으로 재사용하지 않는다. 단, 아래 사용자 확정 영양소 6개 소제목은 그대로 사용한다.
- 실제 검색량 자료가 없으면 검색량·노출률 수치를 만들지 않는다.
- FAQ·자료 출처는 보조 영역이며 핵심 H2 6개에 포함하지 않는다.

## 5. 기본 구조와 HTML 표현
신규 및 전체 수정은 다음 순서를 사용한다.

`대표 이미지 → 짧은 도입 → 핵심만 먼저 6카드 → 사용자 확정 ①~⑥ → FAQ → 자료 출처`

- 하단에 같은 내용을 반복하는 `핵심 정리` H2는 만들지 않는다.
- 핵심 H2는 정확히 아래 6개 축을 사용한다.
- 상단 6카드는 `효능 / 누가 / 복용 / 기간 / 조합 / 주의` 순서로 고정한다.
- 카드는 본문을 다 쓴 뒤 최종 수치와 표현을 압축한다. 카드에만 있는 새로운 주장·수치·제품을 만들지 않는다.
- 본문 HTML은 정보의 역할에 맞게 구성한다. 설명은 `<p>`, 여러 항목 비교는 `<ul><li><strong>항목명:</strong> ...</li></ul>`, 수치 비교는 `<table>`, 이미지는 `<img>`를 사용한다.
- ②·③·⑤·⑥에서 서로 다른 변화·섭취법·조합·주의·제품 선택 포인트가 여러 개라면 **항목형 리스트 구조를 우선 사용해 카드로 읽히게 한다.**
- ④의 TOP7·함량은 **표가 중심**이다. 카드 목록으로 바꾸지 않는다.
- 형광펜만 추가한 평문이 아니라, 독자가 눈으로 구조를 구분할 수 있는 **카드·표·이미지·문단의 조합**으로 완성한다.

## 6. 사용자 확정 영양소 6개 소제목
아래 문구·순서·의미는 사용자 승인 없이 변경하지 않는다.

### ① 정의와 주요 성분 및 작용은 무엇인가?
- 무엇인지, 주요 성분이 무엇인지, 몸에서 어떤 역할을 하는지 쉽게 설명한다.
- 비슷한 성분과 혼동하기 쉬우면 차이를 짧게 정리한다.
- 기전은 효능을 이해하는 데 필요한 만큼만 쓴다.
- 전문용어가 꼭 필요하면 `쉬운 한국어(전문용어)` 순서로 첫 등장 한 번만 설명한다.

### ② 한 달 복용 후 기대되는 신체 변화와 권장 대상은 누구인가?
- 첫 문장에서 **한 달 정도 섭취했을 때 독자가 기대할 수 있는 변화**를 먼저 설명한다.
- 그 변화가 특히 유용한 사람을 구체적으로 연결한다.
- 필요한 경우 `대상 / 실제 섭취량 / 기간 / 변화`를 쉬운 문장으로 제시한다.
- 서로 다른 변화가 2개 이상이면 항목형 카드로 나눠 `변화 → 누구에게 → 필요한 수치·기간 → 실제 의미`가 한눈에 보이게 한다.
- 특정 사람에게만 해당하는 변화를 모든 사람에게 일반화하지 않는다.
- 독자가 체감하기 어려운 지표만 나열하지 말고 생활에서 이해할 수 있는 의미를 함께 설명한다.

### ③ 일일 권장 섭취량과 효과적인 섭취법은 무엇인가?
- `하루 얼마 / 1회 얼마 / 하루 몇 번 / 언제 / 식전·식후 / 나눠 먹을지 / 얼마나 지속할지`를 독자가 바로 따라 할 수 있게 정리한다.
- 공식 권장량·충분섭취량·상한이 있으면 우선 제시한다.
- 공식 권장량이 없는 성분은 **현재 판매 제품의 표시 섭취량과 실제 복용법을 중심으로 설명한다.**
- 형태나 목적별 섭취법이 다르면 항목형 카드로 나누고, 수치 비교가 있으면 표를 함께 사용한다.
- 원료량과 실제 유효성분량을 구분한다.
- 해외 제품 용법으로 국내 제품 복용법을 덮어쓰지 않는다.
- 임의의 기간이나 용량을 만들지 않는다.

### ④ 풍부한 식품 TOP7과 각 식품의 평균 함유량은 얼마인가?
- 첫 문장과 표가 **어떤 식품에 많이 들어 있고 평균적으로 얼마나 들어 있는지** 바로 답해야 한다.
- 기본 표는 `순위 / 식품 / 평균 함유량 / 기준` 중심으로 구성한다.
- 국내 독자가 실제로 아는 식품명과 원료명을 우선한다.
- 같은 원료를 넣은 가공품 여러 개로 TOP7을 채우지 않는다.
- 성분 자체를 직접 먹는 식품과 그 성분을 이용해 만든 가공·발효식품은 성격이 다르면 구분해 설명한다.
- 실제 평균값만 `평균 함유량`이라고 쓴다. 범위 자료는 범위, 단일 측정값은 단일값으로 표시한다.
- 계산·환산·배합률 적용값을 실제 평균 함유량처럼 만들어 순위에 넣지 않는다.
- TOP7을 채우기 위해 숫자를 만들지 않는다. 확인 가능한 항목이 7개보다 적으면 확보한 식품을 최대한 보여주되, 부족한 이유를 장황하게 설명하지 않는다.
- 제품의 1회 제공량을 식품의 풍부함 순위 근거로 사용하지 않는다.
- 향신료·분말처럼 100g 섭취가 비현실적이면 실제 1회 사용량을 함께 설명한다.
- 분석방법·자료 비교 과정·작성자의 순위 판단 과정은 표의 열이나 본문 중심 내용으로 쓰지 않는다.
- 상세 숫자 작성 규칙은 `docs/NUTRIENT_FOOD_SOURCE_RANKING_GUARD_20261015.md`를 따른다.

### ⑤ 함께 섭취하면 좋은 영양소와 주의할 상호작용은 무엇인가?
- `무엇과 같이 먹으면 좋은가 → 왜 좋은가 → 실제로 어떻게 같이 먹나 → 기대되는 이점 → 중복·상한·약물 주의` 순서로 설명한다.
- 서로 다른 조합이 여러 개면 조합별 카드로 나눠 읽히게 한다.
- 음식 궁합보다 영양소·기능성 성분 조합을 우선한다.
- 실제로 도움이 되는 조합만 제시하고 개수를 채우려고 약한 조합을 추가하지 않는다.
- 약물과 함께 먹을 때 실제 주의가 필요한 경우 약 이름·성분군과 행동 기준을 쉽게 설명한다.
- 기전 설명이 실제 섭취 방법보다 길어지지 않게 한다.

### ⑥ 결핍 및 과다 복용의 위험, 예방 가능한 질병과 추천 제품은 무엇인가?
- 결핍 시 나타날 수 있는 변화·위험군·확인 방법을 설명한다.
- 과다 복용 시 실제 부작용·상한·중단 또는 상담 기준을 설명한다.
- 결핍·과다·예방·제품 선택처럼 역할이 다른 정보는 항목형 카드로 나눠 빠르게 읽히게 한다.
- 예방에 도움이 되는 질병·상태는 독자가 이해할 수 있는 범위에서 구체적으로 설명하되 과장하지 않는다.
- 제품은 실제 판매 중인 제품을 확인하고 `제품명 / 1회량 / 하루 섭취법 / 핵심 성분량 / 선택 포인트` 중심으로 소개한다.
- **비교 가능한 실제 판매 제품이 3개 이상 확보되면 기본적으로 `추천 제품 TOP3`를 작성한다.** 3개를 신뢰성 있게 확보할 수 없으면 억지로 순위를 만들지 않고 대표 제품 예시만 제시한다.
- TOP3는 판매량·리뷰 수·광고 노출 순위가 아니라 **핵심 기능성 원료의 적합성, 하루 유효성분량, 지표성분·원료 규격, 부원료의 실질적 의미, 복용 편의성, 불필요한 복합성·상호작용 부담**을 우선해 평가한다.
- 가격은 실제 구매 판단에 도움이 될 때만 보조 요소로 쓰며, 가격만으로 순위를 뒤집지 않는다. 가격이 자주 바뀌면 정확한 금액보다 가격대·1일 비용 또는 `가격 변동 가능`을 표시한다.
- 성분 수가 많다는 이유만으로 상위 제품으로 평가하지 않는다. 추가 성분 때문에 금기·상호작용·중복 섭취 위험이 커지면 순위를 낮추거나 특정 대상용 제품으로 분리한다.
- TOP3 표는 기본적으로 `순위 / 제품 / 핵심 구성 / 장점 / 아쉬운 점·주의 / 추천 대상`을 사용한다. 필요한 경우 `1회량 / 하루 섭취법 / 1일 비용`을 추가한다.
- 각 순위에는 **왜 그 순위인지 한 문장으로 설명할 수 있어야 하며**, 독자가 어떤 제품이 자기 목적에 맞는지 바로 판단할 수 있게 한다.
- 제품이 동일 원료·동일 함량이라면 부원료, 섭취 횟수, 원료 공개 수준, 안전성 부담, 가격 대비 구성을 비교한다.
- 객관적 판매순위·판매량·리뷰 자료가 없으면 `판매 1위`, `가장 인기`라고 쓰지 않는다. TOP3의 `1위·2위·3위`는 **이 글의 성분 평가 기준에 따른 추천 순위**임을 명확히 한다.
- 제품 선택을 다른 H2에서 반복하지 않는다.
- 실제 응급 증상·중요 금기는 행동 기준을 분명히 적는다.

## 7. 자료와 출처 사용
- 자료는 **작성자가 숫자와 사실을 정확하게 확인하기 위한 도구**다.
- 공개 본문에서는 기관명·DB명·문서 제목보다 독자가 필요한 답을 먼저 쓴다.
- 출처는 필요한 문장 뒤의 간결한 주석 또는 하단 `자료 출처`에 정리한다.
- 출처가 많다는 이유로 본문 품질이 높아지는 것으로 판단하지 않는다.
- 사실 확인 메모·비교 메모·QA 메모를 공개 본문에 복사하지 않는다.

## 8. 쉬운 문체와 정보 밀도
- 제목·H2·본문·표·핵심카드는 한국 일반 독자가 실제로 쓰는 말을 기본값으로 한다.
- 학명·영문명·균주명·가공공정명·전문 약어는 정확성이나 실제 선택에 꼭 필요할 때만 사용한다.
- 기본 표현 순서는 **`쉬운 답 → 필요한 숫자·조건 → 실제 행동`**이다.
- 같은 수치를 도입·카드·본문·FAQ에서 반복하지 않는다.
- 장점·효능·섭취법·함량·조합 같은 실용 정보가 글의 중심이 되게 한다.
- 안전 경고는 관련 H2 또는 ⑥에 모으고, 일반적인 부정 문장으로 글의 첫 인상이나 분량을 채우지 않는다.
- 글이 짧은지는 품질 기준이 아니다. **독자가 해당 H2의 질문을 읽고 추가 검색 없이 핵심 판단을 할 수 있는지**를 정보 충분성 기준으로 삼는다.

## 9. 상단 요약·강조
- source HTML의 상단 요약은 다음 의미 구조를 사용한다.
  `<blockquote><strong>핵심만 먼저:</strong> <strong>효능</strong> ...<br><strong>누가</strong> ...<br><strong>복용</strong> ...<br><strong>기간</strong> ...<br><strong>조합</strong> ...<br><strong>주의</strong> ...</blockquote>`
- 공통 `publishing/direct-design.mjs`가 PC 2열·모바일 1열 카드로 렌더링한다. 원고별 inline CSS를 추가하지 않는다.
- 영양소 direct/SP1 강조 누락 방지 하한은 **strong25·mark14·mark>u>strong8**이다.
- 하한을 채우기 위해 없는 효능·수치·위험을 만들지 않는다.
- 강조의 첫 기준은 `현재 H2의 질문에 가장 직접 답하는가`다.
- strong은 정의·핵심 수치·보조 설명, mark>strong은 핵심 답과 실제 행동 정보, mark>u>strong은 가장 중요한 효능·실천 행동에 우선한다.
- `positive / info / caution / negative` 톤은 의미 구분용이며 색을 채우기 위해 문장을 만들지 않는다.
- 즉시 위해를 막아야 하는 금기·응급 행동은 예외적으로 강하게 강조할 수 있다.
- **형광펜 문장만 위에서 아래로 읽어도 ① 정의·작용, ② 변화·대상, ③ 섭취량·섭취법, ④ 식품·함량, ⑤ 조합·상호작용, ⑥ 결핍·과다·예방·제품 선택의 핵심 답을 빠짐없이 회수할 수 있어야 한다.**
- 형광펜은 본문의 압축판이다. 경고·주의만 몰아서 강조하지 않고 효능·수치·섭취법·식품·조합·제품 선택을 우선 배치한다.
- 최고강조 `mark>u>strong`은 각 소제목에서 독자가 가장 먼저 기억해야 할 답과 행동에 사용한다.

## 10. 이미지·내부링크
- 신규 및 전체 수정은 서로 다른 본문 이미지 최소 3개를 사용한다.
- HTTPS·alt·원출처·저작자·라이선스·중복을 확인한다.
- 대표 이미지는 성분의 실제 사용 목적·섭취 맥락을 일반 독자가 즉시 이해할 수 있는 실사를 우선한다.
- imageReview와 visualChecked는 공통 direct 계약을 따른다. 실제 현재 revision을 확인하지 않고 visualChecked=true를 복사하지 않는다.
- 내부링크는 실제 관련 글만 연결한다.

## 11. 작성 순서와 저장 전 내용 검토
작성 흐름은 다음을 기본으로 한다.

`검색 의도·중복 → 독자 질문 → 사실·숫자 확인 → 사용자 확정 6개 H2 작성 → 상단 6카드 → HTML 카드·표 구조 → 강조·이미지·링크 → 내용 검토 → Gate 0`

저장 전 한 번만 확인한다.
1. 사용자 확정 6개 소제목의 문구·순서·의미를 임의 변경하지 않았는가?
2. 각 H2 첫 문장이 질문에 바로 답하는가?
3. 본문이 독자에게 필요한 정보인가, 작성자의 확인 과정 설명인가?
4. 자료 부족·한계·반박 문장이 실용 정보를 밀어내고 있지 않은가?
5. ②가 한 달 변화와 권장 대상을 독자가 이해할 말로 직접 설명하는가?
6. ③이 실제 하루 섭취량과 먹는 방법을 바로 보여주는가?
7. ④가 TOP7과 각 식품의 함유량을 가장 먼저 보여주며, 제품 1회 제공량을 풍부함 순위로 오해하게 만들지 않는가?
8. ⑤가 실제 조합과 상호작용 행동을 알려주는가?
9. ⑥이 결핍·과다·예방·제품을 실제 선택에 도움이 되게 설명하는가?
10. 추천 제품 TOP3를 작성했다면 판매량이 아니라 성분·함량·규격·안전성·복용 편의성 기준으로 순위를 설명할 수 있는가?
11. 서로 다른 항목이 여러 개인 H2가 카드형 리스트 또는 표로 구조화되어 있는가?
12. 형광펜만 읽어도 ①~⑥ 핵심 답이 모두 이어지는가?
13. 상단 카드·강조·표·이미지가 본문 핵심 답과 일치하는가?

- 별도 AI 의미 PASS·자동 재작성 루프를 만들지 않는다.
- Gate 0·preflight·공개검증에서 같은 의미·문체 검토를 반복하지 않는다.

## 12. Gate 0·GitHub 저장
- GitHub 쓰기 전에 완성 JSON 전체와 sourceId·articleId·title·digest·검사 상태를 보존한다.
- 실제 commit SHA에 고정한 파일을 다시 읽고 내용과 digest가 일치해야 `GITHUB_SOURCE_CONFIRMED`다.
- WRITE_BLOCKED·파일 부재·조회 불가·내용 불일치를 구분한다.
- 재개 시 같은 source의 저장·원장·실행 상태부터 확인한다.

## 13. 표준 실행·공개 검증·복구
- 영양소 저장소 저장만으로 발행 완료라고 하지 않는다.
- 신규는 `publish-posts.yml`, 기존 수정은 `direct-author-update.yml → update-posts.yml`을 사용한다.
- 자동 실행과 수동 실행을 겹치지 않는다.
- 제출 전 실패이고 제출 단계가 시작되지 않았다면 원인을 직접 수정하고 같은 source로 재실행한다.
- 이미 PASS한 검사와 원고 확인을 변경 근거 없이 반복하지 않는다.
- HTTP200·SUBMIT_CLICKED·Actions SUCCESS만으로 완료라고 하지 않는다.
- 해당 source의 `PUBLIC_VERIFIED`와 신규 `published`/기존 `updated` 원장을 확인한다.
- 제출 후 상태가 불명확하면 임의 재제출하지 않고 읽기 전용 복구 경로를 사용한다.

## 14. 변경 보호·보고
- 승인 없는 reset·force push·기존 원고/원장 삭제·중복 발행·URL·articleId·카테고리·스킨·광고 변경을 하지 않는다.
- 작성·내용 검토·기술 검사·GitHub 저장 확인·실행·제출·공개 검증을 구분한다.
- 확인하지 않은 결과를 PASS라고 하지 않는다.
- 최종 보고는 source SHA·Run·공개 URL·원장 상태·중요한 문제만 간결하게 작성한다.
