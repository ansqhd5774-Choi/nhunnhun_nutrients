## R8.12 핵심 구조

영양소 글은 독자가 짧게 읽어도 실제 선택과 복용에 필요한 정보를 얻도록 다음 흐름을 사용합니다.

0. **상단 `핵심만 먼저` 6카드 요약** — 대표 이미지와 짧은 도입 다음에 `효능 / 누가 / 복용 / 기간 / 조합 / 주의`를 압축합니다. PC는 2열, 모바일은 1열의 승인된 공통 카드 디자인을 사용하며 하단 `핵심 정리`는 만들지 않습니다.
1. **정의·주요 성분·작용** — 전문용어는 첫 등장에 쉬운 말로 바로 풀어 설명
2. **효능·기대 변화·권장 대상·제품 형태 선택** — 확인된 효능에서 해당 사람을 역으로 연결
3. **실제 섭취량·복용법·기간·대표 제품** — 몇 mg, 몇 알, 하루 몇 회, 언제, 얼마나 오래, 현재 제품 예시까지 실용적으로 설명
4. **풍부한 식품 TOP7·평균 함량** — 동일 DB·동일 기준으로 비교하고 실제 먹는 양도 함께 설명
5. **함께 섭취할 영양소·보충제 조합** — 음식 궁합보다 영양소+영양소 조합을 우선하고 이유·복용법·중복 주의를 함께 설명
6. **결핍·과다 섭취** — 제품 선택을 반복하지 않고 부족·과량·상한·상담 기준에 집중

### 기존 글 전체 최신화 원칙

- 기존 글에서 유지하는 것은 **숫자 URL·articleId와 현재도 유효한 사실·출처 자산**입니다.
- 기존 H2 순서·소제목 문구·문단 배열은 새 원고의 골격으로 재사용하지 않습니다.
- 먼저 ①~⑥의 **빈 H2 골격을 새로 만든 뒤** 최신 조사 결과를 배치하고, 기존 글에서는 재확인된 사실만 옮깁니다.
- ①~⑥ 의미 대조는 저장 전 `내용 검토`에서 **한 번만** 수행합니다. Gate 0·preflight·공개 검증은 같은 의미 검토를 반복하지 않습니다.

## 승인된 상단 요약 카드

source HTML은 아래 의미 구조를 사용합니다.

```html
<blockquote><strong>핵심만 먼저:</strong>
<strong>효능</strong> ...<br>
<strong>누가</strong> ...<br>
<strong>복용</strong> ...<br>
<strong>기간</strong> ...<br>
<strong>조합</strong> ...<br>
<strong>주의</strong> ...
</blockquote>
```

공통 `publishing/direct-design.mjs`가 이를 `QUICK GUIDE · 핵심 요약 · 30초 안에 보는 핵심 기준` 카드로 변환합니다. 각 글에 별도 inline CSS를 만들지 않습니다.

- 카드 순서는 **효능 → 누가 → 복용 → 기간 → 조합 → 주의**로 고정합니다.
- 각 카드는 한 가지 답만 짧게 전달합니다. 상세 연구명·긴 기전·출처 설명은 본문에 둡니다.
- 카드에서 가장 먼저 눈에 띄어야 하는 것은 **효능·권장 대상·실제 복용·조합 같은 건강 개선 정보**입니다. 일반적인 주의·금기 문구는 내용을 유지하되 형광펜이나 최고강조의 중심으로 만들지 않습니다.
- 즉시 중대한 위해를 막아야 하는 응급 행동·절대적 금기만 예외적으로 최고강조를 사용할 수 있습니다.
- 공식 권장량이나 상한이 없으면 빈칸을 만들지 않고 “공식 권장량 없음·제품 라벨 우선”처럼 사실대로 씁니다.
- 카드의 수치·제품·기간·조합은 상세 본문과 정확히 일치해야 합니다.
- 하단에는 같은 내용을 다시 요약하지 않고 FAQ → 자료 출처로 끝냅니다.
- 승인된 카드 구조는 공통 러너 회귀 테스트로 보호합니다.

## 강조 우선순위·색상

- 강조를 고르는 **첫 기준은 긍정/부정이나 색이 아니라 현재 H2의 질문에 가장 직접 답하는가**입니다.
- 각 H2에서 먼저 핵심 답을 고른 뒤, 그 안에서 독자의 건강 개선·선택·복용에 가장 도움이 되는 문장을 `mark` 또는 최고강조로 올립니다.
- **strong**: 정의·핵심 수치·보조 설명.
- **mark>strong**: 현재 H2의 핵심 답 가운데 확인된 효능·권장 대상·실제 섭취량·복용 시간·기간·조합 이유처럼 바로 건강 행동으로 옮길 정보.
- **mark>u>strong**: 그 글에서 가장 중요한 건강 개선 효능 또는 실천 행동을 우선합니다.
- ⑥처럼 **결핍·과다 자체가 질문인 H2**에서는 결핍 예방·대표 증상·과다 위험·상한·중단 기준이 핵심 답입니다. 위험 정보라는 이유만으로 자동으로 강조를 낮추지 않습니다.
- 반대로 “식품 우선”, “라벨 확인” 같은 일반 실천 팁이 유용하더라도 H2의 핵심 답보다 더 강하게 보이게 하지 않습니다.

공통 렌더러는 다음 네 가지 의미 톤을 지원합니다.

| 톤 | 용도 | 표시 |
| --- | --- | --- |
| `positive` | 확인된 효능·개선 결과·권장 행동 | 연녹색 |
| `info` | 권장량·복용 시간·기간·중립적 선택 기준 | 연파랑 |
| `caution` | 상한·상호작용·주의 행동 | 연주황 |
| `negative` | 실제 부작용·과다 위험·중단 기준 | 연분홍/적색 계열 |

예시는 `<mark data-tone="positive"><strong>...</strong></mark>`이며 최고강조도 같은 `data-tone`을 유지합니다. class 없는 기존 `<mark>`는 기존 노란색으로 그대로 렌더링됩니다.

- 새 글·전체 최신화는 **실제 내용에 맞는 범위에서 2~4개 톤을 자연스럽게 섞을 수 있습니다.** 모든 색을 의무적으로 사용할 필요는 없습니다.
- 같은 성격의 정보는 같은 톤을 우선하고, 한 문단에서 여러 색을 난잡하게 섞지 않습니다.
- 색을 채우기 위해 효능·위험·주의를 새로 만들지 않습니다.
- 임의 HEX·inline style을 원고마다 추가하지 않고 공통 렌더러의 승인 톤만 사용합니다.
- 같은 환산식·권장량·경고를 카드와 본문에서 반복해 형광펜 처리하지 않습니다.
- 강조와 색상 의미 검토는 저장 전 `내용 검토`에서 **한 번만** 하고 Gate 0·preflight·공개 검증에서 반복하지 않습니다.

## 쉬운 문체 기준

- 기본 독자는 영양학 전공자가 아닌 한국 일반 독자이며, **중학생~고등학생이 한 번 읽고 핵심 뜻을 이해할 정도**를 기본 난이도로 봅니다.
- 전문용어는 필요한 경우에만 쓰고 첫 등장에 바로 쉬운 말로 풉니다. 이후에는 쉬운 표현을 우선합니다.
- `전구체`, `상피세포`, `생체이용률`, `무작위 대조시험`, `교차시험` 같은 용어는 그대로 던지지 않고 먼저 일상적인 말로 뜻을 설명합니다.
- `RAE`, `AREDS2`, `RDA`, `UL` 같은 약어는 꼭 필요한 경우에만 쓰며 처음 한 번 뜻을 설명한 뒤 쉬운 표현으로 바꿉니다.
- 연구 설계명이 결론 이해에 필요하지 않으면 `사람 연구`, `임상시험`처럼 단순화합니다.
- 한 문장에는 가능하면 핵심 개념 하나와 중요한 숫자 하나 정도만 둡니다. 약어·환산식·전문용어·예외 조건을 한 문장에 겹치지 않습니다.
- 쉬운 글을 만들기 위해 정보를 빼지 않습니다. **정보량은 유지하고 `쉬운 결론 → 필요한 숫자·조건 → 전문 근거` 순서로 설명합니다.**
- 이 난이도 검토는 저장 전 `내용 검토`에서 **한 번만** 수행하며 별도 가독성 점수·자동 차단기·반복 재검사는 추가하지 않습니다.

## 저장 직전 작성 검토

- 전문성은 어려운 용어를 많이 쓰는 것이 아니라 **정확한 수치·조건·행동을 짧게 전달하는 것**으로 판단합니다.
- 각 문단은 가능하면 `답 → 이유/수치 → 행동` 순서로 2~4문장 안에서 끝냅니다.
- 저장 전 문체 검토는 **각 H2 첫 답과 핵심 문단이 일반 독자에게 한 번에 이해되는가**를 한 번만 보고, 설명 없는 전문용어·약어·연구 설계명·숫자와 예외 조건이 겹친 문장만 쉽게 고칩니다.
- 저장 전 강조 검토는 **각 H2의 가장 강한 강조가 그 H2 질문의 핵심 답인가**를 먼저 보고, 이어서 글 전체에서 효능·대상·섭취법·조합 같은 건강 개선 정보가 우선되는지 확인합니다. 색상은 같은 검토 안에서 의미와 톤이 맞는지만 함께 확인합니다.
- ②의 권장 대상은 “건강을 챙기고 싶은 사람”처럼 일반적으로 만들지 않고 **실제 효능에서 직접 도출**합니다.
- ③은 공식 권장량·연구 용량·제품 표시량을 구분하고, 현재 국내 제품의 복용법을 소개할 때는 최신 공식 라벨을 확인합니다.
- “가장 인기”라는 표현은 현재 판매순위·판매량·리뷰수 등 객관 자료가 있을 때만 사용하며, 그렇지 않으면 **대표 제품 예시**라고 씁니다.
- ⑤는 `A+B → 이유 → 같이 먹는 방법/시간 → 기대 이점 → 중복·상한·약물 주의` 순서로 작성합니다.
- ⑥에 제품 선택을 다시 넣지 않습니다.
- 확인된 효능·장점을 먼저 설명하고, 일반적인 근거 한계·반박을 반복해 글의 중심을 바꾸지 않습니다. 실제 금기·상호작용·응급 행동은 유지합니다.

## 이미지 선택 기준 — 독자 관련성 우선

- 대표 이미지는 **성분의 실제 사용 목적·효능·섭취 맥락을 일반 독자가 즉시 이해할 수 있는 실사**를 우선합니다. 운동 성분이면 실제 운동 장면, 식이 공급원이 중요하면 실제 식품처럼 글의 핵심 검색 의도를 먼저 보여줍니다.
- 분자구조식·결정·현미경 사진·실험실 시각자료는 본문의 작용 설명에 꼭 필요할 때만 보조 이미지로 검토하고, **영양소 대표 이미지(hero)로 사용하지 않습니다.**
- 이미지 3장은 단순히 서로 다른 파일을 채우는 것이 아니라 각각 `대표 맥락 / 실제 활용·효능 / 식품·섭취 또는 안전` 중 해당 글에 필요한 서로 다른 정보를 담당하도록 고릅니다.
- 사진을 넣을 위치의 H2 내용과 직접 연결되는지 확인합니다. H2 4 식품 설명 뒤에 운동 사진을 두는 식의 **위치-내용 불일치도 부적합**으로 봅니다.
- `visualChecked`는 관찰 기록일 뿐 품질 인증이 아닙니다. 개수·alt·라이선스 검사를 통과해도 독자 관련성이 낮으면 교체합니다.
- 실제 시각 점검에서 부적합하다고 확인된 원출처는 `publishing/rejected-hero-sources.mjs`에 등록하고, 공통 러너는 영양소 hero의 구조식·결정·현미경 계열 파일명도 결정론적으로 차단합니다.

기존 원고의 `imageReview`를 재사용할 때 `src`, `alt`, `role`, `composition`, `sourcePage`, `author`, `license`는 재사용할 수 있지만 `visualChecked`는 새 source로 복사하지 않습니다. 현재 revision에서 실제 원본을 다시 확인했을 때만 `visualChecked:true`를 기록하며 이 값은 발행 필수 게이트가 아닙니다.

실제 시각 점검에서 대표 이미지로 부적합하다고 확인된 원출처는 다시 hero로 선택하지 않습니다. 공통 러너의 `publishing/rejected-hero-sources.mjs`에 등록된 원출처는 direct preflight에서 차단됩니다.

이 저장소에 원고를 저장하는 것만으로 Tistory 발행이 시작됐다고 보지 않습니다. 동일 source가 공통 러너에 접수됐는지 확인하고 workflow와 source별 원장의 `PUBLIC_VERIFIED`까지 별도로 확인합니다.
